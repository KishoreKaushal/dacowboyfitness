Key idea & scope

Turn the static marketing SPA into an app that can sell and play one paid course. Three tracks, one deliverable:

  1. Frontend course pages — add routing and a small layered architecture (lib/, composables/, views/, a typed course catalog), so a real course page is segregated from the marketing landing and each concern is its own module.
  2. Gmail login — Firebase Authentication (Google provider) on the client; every backend function verifies the Firebase ID token server-side (the identity trust boundary).
  3. Curriq integration (Model B) — a server function holds a Curriq read key, checks the Firestore entitlement, and returns short-lived Mux playback tokens. Plus a runbook to add a new course through Curriq (write-key upload script → catalog entry → price → deploy).

In scope

  • vue-router + /course/:id player page.
  • useAuth (Google), useCourseAccess, lib/firebase, lib/api.
  • Typed paid-course catalog (site id ⇄ Curriq id, decoupled).
  • 3 functions: createOrder, razorpayWebhook, course (Model B).
  • Firestore entitlements + security rules.
  • scripts/upload-course.mjs to push a course + 5 videos into Curriq.

Out of scope (this beta)

  • Model A / SSO shared key (Curriq Work Package G) — not needed under Model B.
  • Per-course entitlement inside Curriq — stays customer-side (roadmap).
  • Live Razorpay keys (sandbox only until verified).
  • Progress tracking / analytics / multi-course catalog page.
  • A users/{uid} profile mirror — Firebase Auth already holds the profile; skip for beta.
The full function bodies, Firestore rules, security checklist and cost table live in the companion guide (ai-docs/guides/09Aug26-14h52m-auth-payment-course-unlock.html). This plan is the ordered, executable build; it inlines every snippet needed so it can be run without opening the guide, and points to guide sections for extra rationale.

Decoupling that makes it modular: the browser only knows a site course id (e.g. cowboy-way). The curriqCourseId lives in the catalog for display and, authoritatively, in the server COURSES map. Swapping the LMS later touches only functions/, not the UI.

Dependency boundary — firebase vs firebase-admin

The frontend (src/, built by Vite → dist/) and the backend (functions/, built by its own tsc → Cloud Functions runtime) are two separate npm projects with two separate dependency sets. The browser SDK and the server SDK are different packages — never import a server package into src/.

PackageSide · folderIn dist/?Role
firebase (client SDK)Frontend · src/Yes — public configGoogle sign-in, reactive auth state, client read of own entitlement.
vue-routerFrontend · src/YesRouting (/, /course/:id).
@mux/mux-playerFrontend · src/YesVideo element.
firebase-admin (server SDK)Backend · functions/NoverifyIdToken; Admin Firestore writes (bypasses security rules).
firebase-functionsBackend · functions/NoFunction runtime + secret binding.
razorpayBackend · functions/NoServer-side order creation.
@curriq/client + CURRIQ_READ_KEYBackend · functions/NoModel B: course outline + Mux playback tokens.
firebase (client) ≠ firebase-admin (server). The client SDK is meant to ship in the bundle — it carries only the public web config and can do nothing an unauthenticated browser couldn't. firebase-admin is a different package that must live only in functions/: importing it into src/ would fail in the browser (no Node/service-account) and defeat the isolation. Rule of thumb — if a module needs a secret or an Admin privilege, it belongs in functions/. Enforced structurally: tsconfig.app.json compiles only src/**, and Vite bundles only what src/main.ts imports, so functions/ is unreachable from the build graph (see Phase 4 · Build isolation).

// src/lib/api.ts
import { auth } from './firebase'

export async function apiPost<T>(path: string, body: unknown): Promise<{ status: number; data: T }> {
  const token = await auth.currentUser?.getIdToken()
  const res = await fetch(path, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
    },
    body: JSON.stringify(body),
  })
  const data = (await res.json().catch(() => ({}))) as T
  return { status: res.status, data }
}

2.4 — composables/useCourseAccess.ts

// src/composables/useCourseAccess.ts
import { ref } from 'vue'
import { apiPost } from '../lib/api'

export type Lesson = { title: string; playbackId: string; token: string }
export type AccessState = 'idle' | 'loading' | 'anon' | 'not_entitled' | 'ready' | 'error'

export function useCourseAccess() {
  const state = ref<AccessState>('idle')
  const lessons = ref<Lesson[]>([])

  async function load(courseId: string, signedIn: boolean) {
    if (!signedIn) { state.value = 'anon'; return }
    state.value = 'loading'
    const { status, data } = await apiPost<{ lessons: Lesson[] }>('/api/course', { courseId })
    if (status === 403) { state.value = 'not_entitled'; return }
    if (status !== 200) { state.value = 'error'; return }
    lessons.value = data.lessons
    state.value = 'ready'
  }

  return { state, lessons, load }
}

4.1 — scaffold

firebase init functions          # TypeScript; creates functions/ with package.json + tsconfig
cd functions && npm i razorpay @curriq/client
Build isolation — the backend never lands in the frontend bundle. This is structural, not a flag:
  • Separate project. functions/ is a sibling of src/ with its own package.json / tsconfig.json / node_modules. Vite and vue-tsc for the site never enter it.
  • TS scope. tsconfig.app.json includes only src/** — functions/ is outside it, so npm run build (vue-tsc -b && vite build) never type-checks or emits it.
  • No import edge. Vite bundles only what is reachable from index.html → src/main.ts → imports. Nothing in src/ imports from functions/; the only link is a runtime HTTP call to /api/*. No static import ⇒ the bundler cannot pull backend code or secrets into dist/.
  • Separate artifacts. deploy --only hosting ships only dist/ (hosting.public="dist"); deploy --only functions builds inside functions/ and ships to the Cloud Functions runtime. Two builds, two runtimes, two places.
  • Package split. The browser imports firebase (client SDK, public config — meant to be in dist/). The backend imports firebase-admin (a different package, functions/ only). Under Model B, @curriq/client + CURRIQ_READ_KEY and all Razorpay secrets are referenced only in functions/src/* — never in src/, so they physically cannot appear in the bundle.

4.2 — functions/src/_shared.ts (identity + course map)

// functions/src/_shared.ts
import { initializeApp } from 'firebase-admin/app'
initializeApp()

// site course id → Curriq course id (server-authoritative; browser never sends the Curriq id)
export const COURSES: Record<string, { curriqCourseId: string }> = {
  'cowboy-way': { curriqCourseId: 'REPLACE_WITH_CURRIQ_COURSE_ID' },
}

export function bearer(req: any): string {
  const h = String(req.headers.authorization ?? '')
  if (!h.startsWith('Bearer ')) throw new Error('missing token')
  return h.slice(7)
}

4.3 — createOrder.ts (server-priced order)

// functions/src/createOrder.ts
import { onRequest } from 'firebase-functions/v2/https'
import { getAuth } from 'firebase-admin/auth'
import Razorpay from 'razorpay'
import { bearer } from './_shared'

const rzp = new Razorpay({ key_id: process.env.RZP_KEY_ID!, key_secret: process.env.RZP_KEY_SECRET! })

// price lives on the SERVER — never trust an amount from the browser (Q4)
const PRICE: Record<string, { amount: number; currency: string }> = {
  'cowboy-way': { amount: 49900, currency: 'INR' },   // 499.00 INR, in paise
}

export const createOrder = onRequest({ cors: true, secrets: ['RZP_KEY_ID', 'RZP_KEY_SECRET'] }, async (req, res) => {
  const decoded = await getAuth().verifyIdToken(bearer(req))          // trust boundary #1
  const { courseId } = req.body
  const price = PRICE[courseId]
  if (!price) { res.status(400).json({ error: 'unknown_course' }); return }
  const order = await rzp.orders.create({
    amount: price.amount, currency: price.currency,
    receipt: `${decoded.uid}:${courseId}`,
    notes: { uid: decoded.uid, courseId },                            // carried into the webhook
  })
  res.json({ orderId: order.id, keyId: process.env.RZP_KEY_ID, amount: order.amount, currency: order.currency })
})

4.4 — razorpayWebhook.ts (the only unlock)

// functions/src/razorpayWebhook.ts
import { onRequest } from 'firebase-functions/v2/https'
import { getFirestore } from 'firebase-admin/firestore'
import { createHmac } from 'node:crypto'
import './_shared'

export const razorpayWebhook = onRequest({ secrets: ['RZP_WEBHOOK_SECRET'] }, async (req, res) => {
  const signature = String(req.headers['x-razorpay-signature'] ?? '')   // trust boundary #2
  const expected = createHmac('sha256', process.env.RZP_WEBHOOK_SECRET!)
    .update(req.rawBody)                                                // raw bytes, not parsed body
    .digest('hex')
  if (signature !== expected) { res.status(400).send('bad signature'); return }

  const event = req.body
  if (event.event === 'payment.captured') {
    const { uid, courseId } = event.payload.payment.entity.notes ?? {}
    if (uid && courseId) {
      await getFirestore().doc(`entitlements/${uid}/courses/${courseId}`).set(
        { paid: true, orderId: event.payload.payment.entity.order_id, purchasedAt: Date.now() },
        { merge: true },
      )
    }
  }
  res.json({ ok: true })
})

4.5 — course.ts (Model B: read key → tokens)

// functions/src/course.ts
import { onRequest } from 'firebase-functions/v2/https'
import { getAuth } from 'firebase-admin/auth'
import { getFirestore } from 'firebase-admin/firestore'
import { CurriqClient } from '@curriq/client'
import { bearer, COURSES } from './_shared'

const curriq = new CurriqClient(process.env.CURRIQ_API!, process.env.CURRIQ_READ_KEY!)   // read key

export const course = onRequest({ cors: true, secrets: ['CURRIQ_READ_KEY'] }, async (req, res) => {
  const decoded = await getAuth().verifyIdToken(bearer(req))            // who
  const { courseId } = req.body                                        // site id, e.g. 'cowboy-way'
  const mapped = COURSES[courseId]
  if (!mapped) { res.status(400).json({ error: 'unknown_course' }); return }

  const ent = await getFirestore().doc(`entitlements/${decoded.uid}/courses/${courseId}`).get()
  if (!ent.exists || ent.data()?.paid !== true) { res.status(403).json({ error: 'not_entitled' }); return }

  const outline = await curriq.getCourseOutline(mapped.curriqCourseId)  // one nested call
  const lessons: { title: string; playbackId: string; token: string }[] = []
  for (const m of outline.modules)
    for (const l of m.lessons)
      for (const b of l.blocks)
        if (b.blockType === 'asset' && b.data.presentation === 'video') {
          const pb = await curriq.getVideoPlayback(b.data.assetId)      // Curriq-signed Mux token
          lessons.push({ title: l.title, playbackId: pb.playbackId, token: pb.token })
        }
  res.json({ lessons })                                                 // browser gets only Mux tokens
})

Add a new course through Curriq

Authoring is a one-time write-key script (there is no Curriq authoring UI yet — ledger Work Package H). It runs from your machine, not from the functions.

Runbook

  1. Curriq dashboard → API tokens → create a write key. Export CURRIQ_API + CURRIQ_WRITE_KEY.
  2. Run the uploader (below) with your 5 video files. It prints the courseId.
  3. Paste that id into two places: src/features/courses/catalog.ts (curriqCourseId, display) and functions/src/_shared.ts COURSES (authoritative).
  4. Add the site id + amount to the PRICE map in createOrder.ts.
  5. Deploy: npm run build && firebase deploy --only hosting,functions.

scripts/upload-course.mjs

// scripts/upload-course.mjs  — run:  node scripts/upload-course.mjs "The Cowboy Way" ./v1.mp4 ./v2.mp4 …
import { readFile } from 'node:fs/promises'
import { CurriqClient } from '@curriq/client'

const [title, ...files] = process.argv.slice(2)
const client = new CurriqClient(process.env.CURRIQ_API, process.env.CURRIQ_WRITE_KEY)  // write key
const slug = title.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')

// 1) course + one module
const course = await client.createCourse({ slug, title, visibility: 'AUTHENTICATED' })
const mod = await client.createModule(course.id, { title: 'Lessons' })

// 2) each video → upload → wait READY → lesson with an asset block
let n = 1
for (const path of files) {
  const { assetId, uploadUrl } = await client.createVideoUpload({ accessMode: 'AUTHENTICATED' })
  await fetch(uploadUrl, { method: 'PUT', body: await readFile(path) })
  let a
  do { await new Promise((r) => setTimeout(r, 4000)); a = await client.getAsset(assetId) }
  while (a.status !== 'READY')                       // videos aren't playable until Mux finishes
  await client.createLesson(mod.id, {
    title: `Lesson ${n++}`,
    blocks: [{ blockType: 'asset', data: { assetId, presentation: 'video' } }],
  })
}
console.log('courseId =', course.id, ' slug =', slug)   // paste into catalog.ts + COURSES + PRICE
Curriq FREE tier caps (plans/limits.ts): 1 course · 5 videos · 250 MB · 3600 s total · 50 students. The beta course (5 × 2–3 min) fits. Method names/shapes above match the verified Curriq REST + client surface used across the companion docs — do not invent variants.

Notes & risk

  • Blaze card (Q2). Firebase Cloud Functions need the Blaze plan (a card on file); free at beta volume. No card → host the three functions on Cloudflare Workers and keep Auth/Firestore/Hosting on Firebase. Same logic, more plumbing.
  • Two ids, on purpose. Site id (browser/PRICE/route) is decoupled from curriqCourseId (server COURSES). Keeps the UI ignorant of the LMS and makes swapping providers a functions-only change.
  • Expiry is free. Mux tokens are short-TTL and edge-enforced; a fresh play always re-verifies Firebase + entitlement. For a "30-day pass" add expiresAt to the entitlement doc and reject when now > expiresAt before issuing (guide §Isolation & expiry).
  • @curriq/client is server-only here. Under Model B it never ships to the browser; the read key would grant tenant-wide playback if leaked, so it stays a function secret (rotate on leak).
  • vue-router + Firebase Hosting. History mode is safe because ** → /index.html already exists; the only addition is putting /api/* rewrites ahead of it.
  • Curriq authoring gap. No dashboard to create courses yet → the upload script is the interim path (ledger Work Package H). When an authoring UI lands, the script becomes optional; nothing else changes.
  • Rejected: Razorpay → Curriq direct unlock. Curriq has no unlock endpoint / entitlement store; wiring Razorpay to it would need a product feature. The entitlement stays in your Firestore (D2).
